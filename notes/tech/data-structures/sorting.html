Sorting questions usually test the trade-off: time, space, stability, and when the data shape makes a special algorithm worth it.

Common interview sorting algorithms

Divide and conquer

Merge sort

Split the array into halves, sort each half, then merge the results. It is stable, has predictable O(n log n) time, and is often used when you want a reliable sort without worrying about partitioning corner cases. 

void mergeSort(int[] nums, int left, int right) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;
    mergeSort(nums, left, mid);
    mergeSort(nums, mid + 1, right);
    merge(nums, left, mid, right);
}

void merge(int[] nums, int left, int mid, int right) {
    int[] temp = new int[right - left + 1];
    int i = left, j = mid + 1, k = 0;

    while (i <= mid && j <= right) {
        if (nums[i] <= nums[j]) temp[k++] = nums[i++];
        else temp[k++] = nums[j++];
    }

    while (i <= mid) temp[k++] = nums[i++];
    while (j <= right) temp[k++] = nums[j++];

    for (int idx = 0; idx < temp.length; idx++) {
        nums[left + idx] = temp[idx];
    }
}

Common interview angle: “Can you sort this in O(n log n) time while preserving relative order?”

Partitioning

Quick sort

Pick a pivot, partition into smaller and larger values, and recurse on the partitions. It is usually the fastest in practice for arrays in memory and is often tested because the pitfall is choosing the pivot and handling duplicates correctly. 

int partition(int[] nums, int low, int high) {
    int pivot = nums[high];
    int i = low - 1;

    for (int j = low; j < high; j++) {
        if (nums[j] <= pivot) {
            i++;
            int temp = nums[i];
            nums[i] = nums[j];
            nums[j] = temp;
        }
    }

    int temp = nums[i + 1];
    nums[i + 1] = nums[high];
    nums[high] = temp;
    return i + 1;
}

void quickSort(int[] nums, int low, int high) {
    if (low >= high) return;
    int pivotIndex = partition(nums, low, high);
    quickSort(nums, low, pivotIndex - 1);
    quickSort(nums, pivotIndex + 1, high);
}

Best/average: O(n log n). Worst-case: O(n^2) if the pivot is poor every time.

Heap

Heap sort

Build a max-heap or min-heap, then repeatedly remove the root. It guarantees O(n log n) time and uses O(1) extra space if done in-place, but it is less often the “first-choice” answer unless the problem is specifically about a heap or kth largest values. 

void heapSort(int[] nums) {
    int n = nums.length;

    for (int i = n / 2 - 1; i >= 0; i--) {
        heapify(nums, n, i);
    }

    for (int end = n - 1; end > 0; end--) {
        int temp = nums[0];
        nums[0] = nums[end];
        nums[end] = temp;
        heapify(nums, end, 0);
    }
}

void heapify(int[] nums, int size, int root) {
    int largest = root;
    int left = 2 * root + 1;
    int right = 2 * root + 2;

    if (left < size && nums[left] > nums[largest]) largest = left;
    if (right < size && nums[right] > nums[largest]) largest = right;

    if (largest != root) {
        int temp = nums[root];
        nums[root] = nums[largest];
        nums[largest] = temp;
        heapify(nums, size, largest);
    }
}
Insertion

Insertion sort

Build the sorted prefix one element at a time. It is simple, stable, and good for small arrays or nearly sorted data. In interviews, it is often used as a teaching example for why naive sorting can be enough in specific cases. 

void insertionSort(int[] nums) {
    for (int i = 1; i < nums.length; i++) {
        int key = nums[i];
        int j = i - 1;

        while (j >= 0 && nums[j] > key) {
            nums[j + 1] = nums[j];
            j--;
        }
        nums[j + 1] = key;
    }
}

Time: O(n^2). Space: O(1).

Counting

Counting sort

Use when the value range is small and known in advance, such as integers within a limited range like 0 to 100. Count frequencies, then rebuild the output. This can beat comparison sorts when the range is small. 

void countingSort(int[] nums, int min, int max) {
    int range = max - min + 1;
    int[] counts = new int[range];

    for (int num : nums) {
        counts[num - min]++;
    }

    int index = 0;
    for (int value = min; value <= max; value++) {
        while (counts[value - min]-- > 0) {
            nums[index++] = value;
        }
    }
}

Time: O(n + k), where k is the value range. Space: O(k).

Digit-based

Radix sort

Sort by one digit at a time, starting from the least significant digit or the most significant digit depending on the implementation. It is useful for fixed-width integers or strings with limited character sets, and it avoids comparison-based ordering. 

void radixSort(int[] nums) {
    int max = Arrays.stream(nums).max().orElse(0);
    for (int exp = 1; max / exp > 0; exp *= 10) {
        countingSortByDigit(nums, exp);
    }
}

void countingSortByDigit(int[] nums, int exp) {
    int[] output = new int[nums.length];
    int[] counts = new int[10];

    for (int num : nums) {
        counts[(num / exp) % 10]++;
    }

    for (int i = 1; i < 10; i++) {
        counts[i] += counts[i - 1];
    }

    for (int i = nums.length - 1; i >= 0; i--) {
        int digit = (nums[i] / exp) % 10;
        output[counts[digit] - 1] = nums[i];
        counts[digit]--;
    }

    System.arraycopy(output, 0, nums, 0, nums.length);
}

Typical use: sort integers or strings with a bounded digit set, often in O(d(n + k)) time where d is the number of digits.

How to choose

If the question says:

  • “Sort this in general efficiently”: think merge sort or quick sort.
  • “Data is nearly sorted”: insertion sort can be surprisingly effective.
  • “Small fixed value range”: counting sort is a strong answer.
  • “Need a stable sort or you must preserve order”: merge sort is often the safe choice.
  • “Need kth largest / smallest with a heap”: priority queue and heap sort patterns are relevant.

Interview cheat sheet

Quick sort       O(n log n)   O(log n) Average    Fastest in practice for arrays
Heap sort        O(n log n)   O(1)     No         Good for heap-based problems
Insertion sort   O(n^2)       O(1)     Yes        Small or nearly sorted arrays

For interviews, the most commonly tested “big idea” sorting algorithms are merge sort, quick sort, heap sort, and counting sort. If the problem is about order, stability, or a narrow numeric range, the algorithm choice becomes much more obvious.
