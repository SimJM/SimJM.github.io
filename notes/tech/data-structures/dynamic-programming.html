Dynamic programming

Turn repeated subproblems into a state, a transition, and a reliable answer.

Use dynamic programming when subproblems overlap and an answer can be built from answers to smaller subproblems.

Imports for this page: import java.util.Arrays;. This provides Arrays.fill, which sets all entries to an “unreachable” sentinel before the transition runs.

Build a DP solution

1 · State

Define what each entry means

Example: dp[i] is the fewest coins needed to make amount i. A good state is precise enough to compute the next answer.

2 · Base case

Seed known answers

For coin change, zero coins make amount zero, so dp[0] = 0. Initialise impossible states with a sentinel value.

3 · Transition

Connect smaller states

Describe how every legal final choice maps to an earlier state. Then identify where the final answer lives.

Memoisation vs tabulation

Memoisation

Top-down recursion plus a cache. It follows the problem's natural recurrence and computes only states reached by the input. Watch recursion depth in Java.

Tabulation

Bottom-up iteration. It avoids recursion overhead and makes it easier to reduce memory when each state depends only on a recent row or value.

Java template: Coin Change

public int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);
    dp[0] = 0;

    for (int current = 1; current <= amount; current++) {
        for (int coin : coins) {
            if (coin <= current) {
                dp[current] = Math.min(
                    dp[current],
                    dp[current - coin] + 1
                );
            }
        }
    }
    return dp[amount] == amount + 1 ? -1 : dp[amount];
}

State: dp[current] is the fewest coins for current. Base case: dp[0] = 0. Transition: choose each usable final coin, then add one to the best answer for the remaining amount. amount + 1 is a safe sentinel because no valid solution needs more than amount coins when every denomination is at least one. Time O(amount × coins.length); space O(amount).

Practice

  1. Climbing Stairs: identify the Fibonacci-like recurrence.
  2. House Robber: at each house, choose between taking it and skipping it.
  3. Coin Change: decide whether to minimise, maximise, or count solutions.
  4. Longest Common Subsequence: define a two-index state.
