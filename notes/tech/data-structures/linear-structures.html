Linked lists, stacks & queues

Follow pointers deliberately, and use LIFO or FIFO to model the order the problem needs.

Linked lists are ideal when you can work from a node reference; stacks and queues model processing order. In Java, use ArrayDeque for stacks and queues.

Imports for this page: import java.util.ArrayDeque; and import java.util.Deque;. Define ListNode when the platform does not supply it: class ListNode { int val; ListNode next; }.

Recognise the structure

Linked list

Think pointer changes, a dummy head, or fast/slow pointers. Indexed access is O(n); inserting after a known node is O(1).

Stack

Use for matching, undoing, nested structure, or “next greater/smaller” problems. A monotonic stack keeps values in a deliberate order.

Queue

Use when work must be processed first-in, first-out: BFS, task scheduling, and level-order traversal.

Java templates

Reverse a linked list

ListNode previous = null;
ListNode current = head;
while (current != null) {
    ListNode next = current.next;
    current.next = previous;
    previous = current;
    current = next;
}
return previous;

Save next before overwriting the current pointer; otherwise the remainder of the list is lost. At every step, previous is the already-reversed prefix and current starts the unprocessed suffix. Time O(n), space O(1).

Fast and slow pointers

ListNode slow = head;
ListNode fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) return true;
}
return false;

Use this for cycle detection; it also helps find a middle node. If a cycle exists, the fast pointer eventually laps the slow pointer. Check both fast and fast.next before moving it two steps.

Java deque

Deque<Integer> stack = new ArrayDeque<>();
stack.push(value);
int top = stack.pop();

Deque<Integer> queue = new ArrayDeque<>();
queue.offer(value);
int first = queue.poll();

push/pop are stack operations; offer/poll are queue operations.

Monotonic stacks

When to use them

A monotonic stack keeps values in a sorted order while they are still on the stack. The most common use cases are “next greater element”, “previous greater element”, “next smaller element”, “daily temperatures”, and other range queries where an element needs to know the closest item to its left or right that meets a certain condition.

The pattern is simple: iterate left to right, push indices or values onto the stack, and when a new value invalidates the top, pop it until the stack property is restored. The stack stores the important candidates; the popped values are the ones that have already been resolved or no longer matter.

Increasing

Monotonic increasing stack

Keep the stack in increasing order from bottom to top. Pop while the current value is smaller than the top, because the current value can become the next smaller element for the popped item. 

Deque<Integer> stack = new ArrayDeque<>();
for (int i = 0; i < nums.length; i++) {
    while (!stack.isEmpty() && nums[stack.peek()] > nums[i]) {
        int index = stack.pop();
        // nums[index] has a next smaller element: nums[i]
    }
    stack.push(i);
}

This pattern is useful for nearest-smaller, stock-span, and prefix-style queries when the stack is ordered by value rather than by insertion time.

Decreasing

Monotonic decreasing stack

Keep the stack in decreasing order from bottom to top. We pop while the current temperature is greater than or equal to the top, because the current value is the warmer day that resolves the earlier one. 

int[] result = new int[temperatures.length];
Deque<Integer> stack = new ArrayDeque<>();

for (int i = 0; i < temperatures.length; i++) {
    while (!stack.isEmpty() && temperatures[stack.peek()] < temperatures[i]) {
        int previous = stack.pop();
        result[previous] = i - previous;
    }
    stack.push(i);
}
return result;

This is the classic Daily Temperatures pattern: the stack holds indices of temperatures that still need a warmer day to their right. Each pop gives a resolved answer in one pass.

Key invariant: the stack always contains a valid candidate set for unresolved elements. When a new value arrives, you either push it because it is relevant, or pop earlier items that can no longer be the answer. This is why the total work stays O(n).

Why it is efficient

Each index enters the stack once and leaves at most once. That means the total number of push/pop operations is linear. The algorithm does not revisit old values unnecessarily, so it avoids the O(n²) brute-force approach.

A monotonic stack is almost always a signal that the problem is about “nearest greater/smaller” or “span to the right/left”. If you see those words, think stack before brute force.

Practice

  1. Daily Temperatures: use a monotonic decreasing stack of indices.
  2. Next Greater Element I: keep a decreasing stack and resolve values as you scan.
  3. Next Greater Element II: extend the idea to a circular array with a doubled pass.
  4. Largest Rectangle in Histogram: maintain a monotonic increasing stack of bar indices.

Practice
