Coding interviews assess how you reason under incomplete information. Make your reasoning visible: clarify, plan, implement, test, and improve.

The five-step method

1 · Clarify

Turn the prompt into a contract

Restate the input, output, constraints, and edge cases. Ask whether duplicates, empty inputs, negative values, or ordering matter. Do not code until you can give a small example.

2–4 · Plan, implement, narrate

Start with the simple solution

State a brute-force approach, its cost, and why it will not scale. Then introduce the right data structure or pattern. While coding, explain what each variable represents and preserve readable names.

5 · Validate

Walk through and improve

Trace a normal case and an edge case. Give time and space complexity. If there is a trade-off, say when you would choose the alternative.

Complexity in context

Use Big-O to compare growth

O(1) is constant work, O(log n) repeatedly halves a search space, O(n) scans once, and O(n²) usually compares every pair. Include auxiliary memory: a hash map often reduces time at the expense of O(n) space.

Problem: return indices of two values that sum to target. Brute force: try every pair → O(n²) time, O(1) space. Better: store each value's index in a map; for x, look up target - x. Result: O(n) time, O(n) space.
Interview phrase: “I’ll use a map so I can trade linear extra memory for constant-time complement lookups. That reduces the overall pass from quadratic to linear.”

Test before you are asked

Use a compact test matrix

Check the smallest valid input, a typical input, duplicates, boundaries, and invalid or empty input if the contract permits it. Then trace the state rather than merely saying “it works”.

twoSum([2, 7, 11, 15], 9) → [0, 1] twoSum([3, 3], 6) → [0, 1] (duplicate case) twoSum([], 9) → [] (empty case, if allowed)

Practice questions

  1. Two Sum: solve it first with nested loops, then with a hash map. Explain why storing before or after checking matters.
  2. Valid Parentheses: decide which structure tracks unmatched opening brackets and trace "([{}])".
  3. Longest Substring Without Repeating Characters: identify the sliding-window invariant and explain when the left pointer moves.
  4. Merge Intervals: explain why sorting is necessary and state the resulting complexity.
