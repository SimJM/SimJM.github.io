P, NP, NP-hard, and NP-complete

Polynomial time

P

Decision problems a deterministic algorithm can solve in polynomial time, such as O(n), O(n²), or O(n³). Examples include shortest path and minimum spanning tree.

Verifiable

NP

Decision problems where a proposed solution (a certificate) can be verified in polynomial time. NP does not mean “not polynomial”: every problem in P is also in NP.

At least as hard

NP-hard

Problems at least as difficult as every problem in NP. They do not have to be decision problems or belong to NP. Optimisation Knapsack and TSP are NP-hard.

Hardest in NP

NP-complete

Decision problems that are both in NP and NP-hard. A polynomial-time algorithm for any NP-complete problem would prove P = NP.

Important: whether P = NP is unknown. Most computer scientists believe P ≠ NP, but there is no proof.

Reductions

How to show a problem is NP-hard

To prove B is NP-hard:

1. Start with a known NP-hard or NP-complete problem A.
2. Transform an input x of A into f(x), an input of B, in polynomial time.
3. Prove: x is YES for A if and only if f(x) is YES for B.
4. If B were easy, A would also be easy; therefore B is NP-hard.

The direction matters: reduce a known hard problem to the problem you want to prove hard. To prove NP-completeness, additionally show that the target decision problem is in NP by giving a polynomial-time verifier.

0/1 Knapsack

Problem

There are n items. Item i has weight w[i] and value v[i]. Choose every item once or not at all, with total weight at most W, to maximise total value.

Unlike fractional knapsack, you cannot take part of an item. A greedy value/weight ratio is optimal for fractional knapsack but not for 0/1 Knapsack.

Decision vs optimisation

Decision: “Is there a subset with weight at most W and value at least V?” This is NP-complete.

Optimisation: “What is the greatest value within weight W?” This is NP-hard.

Dynamic-programming recurrence

dp[i][capacity] = best value using the first i items
                  with weight limit capacity

Do not take item i: dp[i - 1][capacity]

Take item i, if weight[i - 1] ≤ capacity:
value[i - 1] + dp[i - 1][capacity - weight[i - 1]]

dp[i][capacity] = maximum of the valid choices

The answer is dp[n][W]. The full table takes O(nW) time and O(nW) space.

Java: space-optimised 0/1 Knapsack

public int knapsack(int[] weights, int[] values, int capacity) {
    int[] dp = new int[capacity + 1];

    for (int item = 0; item < weights.length; item++) {
        for (int current = capacity; current >= weights[item]; current--) {
            dp[current] = Math.max(
                dp[current],
                values[item] + dp[current - weights[item]]
            );
        }
    }
    return dp[capacity];
}

Time O(nW); space O(W). Iterate capacity backwards for 0/1 Knapsack. A forward loop would reuse the same item during its iteration, which instead solves unbounded knapsack.

Pseudo-polynomial: O(nW) is polynomial in the numeric value of W, but W takes only log W bits to write down. If W is huge, this is exponential in input length—so it does not contradict NP-hardness.

Travelling Salesman Problem (TSP)

Problem

Given distances between cities, find the shortest tour that starts at a city, visits every city exactly once, and returns to its start.

Decision vs optimisation

Decision: “Is there a tour with cost at most K?” This is NP-complete.

Optimisation: “What is the minimum tour cost?” This is NP-hard.

Baseline

Fix a start city and try every ordering of the rest. This takes O(n!) time, which is impractical even for moderate n.

Held–Karp dynamic programming

State: dp[mask][last]

mask = cities already visited
last = final city in the partial path

dp[mask][last] = minimum cost to start at city 0,
                 visit exactly mask, and finish at last

Transition:
add an unvisited next city to mask

Answer:
minimum dp[allCities][last] + distance[last][0]

This exact algorithm takes O(n² × 2ⁿ) time and O(n × 2ⁿ) space. It improves on factorial brute force but remains exponential.

Java: Held–Karp TSP

import java.util.Arrays;

public int tsp(int[][] distance) {
    int n = distance.length;
    if (n <= 1) return 0;
    int all = (1 << n) - 1;
    int inf = 1_000_000_000;
    int[][] dp = new int[1 << n][n];

    for (int[] row : dp) Arrays.fill(row, inf);
    dp[1][0] = 0; // city 0 is the fixed start

    for (int mask = 1; mask <= all; mask++) {
        for (int last = 0; last < n; last++) {
            if ((mask & (1 << last)) == 0 || dp[mask][last] == inf) continue;

            for (int next = 0; next < n; next++) {
                if ((mask & (1 << next)) != 0) continue;
                int nextMask = mask | (1 << next);
                dp[nextMask][next] = Math.min(
                    dp[nextMask][next],
                    dp[mask][last] + distance[last][next]
                );
            }
        }
    }

    int answer = inf;
    for (int last = 1; last < n; last++) {
        answer = Math.min(answer, dp[all][last] + distance[last][0]);
    }
    return answer;
}

A bitmask stores a visited set: bit i is 1 when city i has been visited. This assumes a complete graph, city 0 as the start, and a square distance matrix. For missing edges, skip them or use a safely large value.

When exact TSP is too expensive: use heuristics or approximation algorithms. For metric TSP—non-negative distances satisfying the triangle inequality—a minimum-spanning-tree traversal gives a 2-approximation. Without those assumptions, there is no comparable general guarantee.
