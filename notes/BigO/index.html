Big O notation describes how an algorithm's resource usage changes as the input size grows. It is a model of growth, not a stopwatch: two algorithms with the same Big O can still have different real-world runtimes because of constants, hardware, input shape, and implementation details.

What Big O means

Definition

Describe the upper growth rate

If an algorithm is O(f(n)), its work is bounded by constant multiples of f(n) for sufficiently large inputs. Here, n is the input size: the number of array elements, characters, vertices, or another meaningful measure.

The notation ignores machine speed and focuses on scalability. An O(n) algorithm generally scales better than an O(n^2) algorithm as n becomes large.

Two resources

Time and auxiliary space

Time complexity estimates how the number of operations grows. Space complexity estimates how much additional memory grows. State them separately: for example, O(n) time and O(n) auxiliary space.

Input storage is often excluded from auxiliary space. If a method creates a result array, ask whether the interviewer counts that output as extra memory and state your assumption.

Core habit: define what n means before counting. In a graph, one input may have V vertices and E edges, so a traversal is usually described as O(V + E), not simply O(n).

Common growth rates

Best scalability O(1) constant one lookup or a fixed number of operations O(log n) logarithmic halve the search space repeatedly O(n) linear visit each item once O(n log n) linearithmic efficient comparison sorting O(n^2) quadratic compare every pair in a simple nested loop O(2^n) exponential explore include/exclude choices O(n!) factorial try every permutation Worst scalability

The order matters for large inputs. For example, if one algorithm performs n operations and another performs n^2, doubling the input roughly doubles the first work but quadruples the second.

O(1) - constant

The work does not depend on input length. Array indexing is constant time because the address can be calculated directly. 

int first = numbers[0];
						int last = numbers[numbers.length - 1];

A loop with a fixed limit, such as ten iterations, is also O(1), even if it appears in the code.

O(log n) - logarithmic

Each step removes a constant fraction of the remaining work. Binary search checks the middle item and discards half the search range each time. 

int left = 0, right = numbers.length - 1;
						while (left <= right) {
							int middle = left + (right - left) / 2;
							if (numbers[middle] == target) return middle;
							if (numbers[middle] < target) left = middle + 1;
							else right = middle - 1;
						}

O(n) - linear

The algorithm performs a constant amount of work per item. A full scan remains linear even if it returns early in some cases; Big O commonly describes the worst case. 

int maximum = numbers[0];
						for (int number : numbers) {
							maximum = Math.max(maximum, number);
						}

O(n log n) - linearithmic

This commonly appears when each of n items is processed across log n levels. Merge sort divides into levels and merges each level in linear total work.

Java's comparison sort implementations are typically O(n log n) in the average or worst case depending on the method and input type. Check the contract when it matters.

How to count code

Drop constants

3n + 7 becomes O(n)

If a method scans an array three times and then performs seven fixed operations, its work is 3n + 7. Big O keeps the growth term and drops constant factors, so the result is O(n).

Keep the dominant term

n^2 + n becomes O(n^2)

When n is large, the quadratic term grows faster than the linear term. Do not write O(n^2 + n) when O(n^2) communicates the asymptotic growth clearly.

Sequential work

Add separate loops

for (int number : numbers) { // O(n)
							process(number);
						}
						for (int number : numbers) { // O(n)
							validate(number);
						}

The loops perform n + n = 2n work, which is O(n), not O(n^2). Sequential blocks add; the dominant term wins afterward.

Nested work

Multiply nested loops

for (int first : numbers) {       // n times
							for (int second : numbers) {  // n per first
								compare(first, second);
							}
						}

The inner loop runs for every outer-loop item, producing n * n = n^2, or O(n^2). This pattern is common in brute-force pair and duplicate checks.

Different input sizes

Do not automatically call every nested loop O(n^2). If one loop uses an array of length m and another uses an array of length n, the complexity is O(mn). This distinction matters when the inputs can have very different sizes.

Space complexity

Input versus auxiliary memory

A few variables such as left, right, and sum use constant auxiliary space: O(1). A hash set that stores up to every input value uses O(n) auxiliary space. 

Set<Integer> seen = new HashSet<>();
						for (int number : numbers) {
							if (!seen.add(number)) return true;
						}
						return false;

This duplicate check is O(n) time on average and O(n) extra space.

Recursion uses the call stack

A recursive method can use memory even when it creates no explicit collection. The maximum number of active calls is its recursion depth. A linked-list recursion with depth n uses O(n) stack space.

A balanced binary-tree traversal has depth O(log n), while a severely skewed tree can have depth O(n). Always analyse the maximum depth permitted by the input.

In-place does not mean zero space: an in-place algorithm usually means O(1) or small extra storage beyond the input, but recursive call frames, library allocations, and output storage may still need to be counted.

Useful complexity reference

Structure or operation Typical complexity Array index access O(1) Array scan O(n) HashMap get/put O(1) average, O(n) worst case HashSet contains O(1) average, O(n) worst case ArrayDeque add/remove at an end O(1) PriorityQueue offer/poll O(log n) PriorityQueue peek O(1) Balanced TreeMap get/put O(log n) Binary search in sorted array O(log n) BFS or DFS adjacency list O(V + E)

These are typical costs, not promises for every implementation. For example, hash tables rely on good hashing and resizing rules, and a binary search tree is only O(log n) when it is balanced or otherwise constrained.

Big O in an interview

A reliable explanation sequence

  1. Define the inputs: say what n, m, V, and E represent.
  2. Describe the work: count scans, lookups, sorting, recursion levels, and repeated operations.
  3. Simplify: drop constants and non-dominant terms only after writing the unsimplified expression.
  4. State time and space: distinguish auxiliary memory from the input and output when relevant.
  5. Discuss assumptions: mention average versus worst-case hashing, balanced versus skewed trees, or early exits.
Example answer: "I scan the array once, so the time complexity is O(n). The set can store every value, so auxiliary space is O(n). Hash-set operations are O(1) on average; in the worst case, they can degrade."

Common mistakes

  • Calling two sequential O(n) loops O(n^2).
  • Ignoring sorting performed before the main algorithm.
  • Forgetting recursion stack space.
  • Using one symbol n for two independent input sizes.
  • Claiming average-case hash-map performance is a guaranteed worst case.

Practice prompts

  • What are the time and space costs of Two Sum with a hash map?
  • Why is binary search O(log n)?
  • What is the complexity of merge sort?
  • Compare recursive DFS and iterative BFS on a graph.
  • Explain why a sliding-window solution can be O(n) even with two while loops.
