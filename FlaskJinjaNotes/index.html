🧠 The Core Mental Model

Think of building a Flask app like running a restaurant.
The customer orders → Kitchen prepares → Dish is plated → Customer receives it.
🍽️ Restaurant🐍 Flask App
👨‍🍳 Kitchen (prepares food)app.py — Python logic
📋 Menu (what's available)Routes — URLs you can visit
🍽️ Plating the dishJinja2 — fills HTML with data
🪟 What customer seesFinal HTML in the browser

🗂️ Project Structure

Flask expects this exact folder layout. The names templates/ and static/ must be precise.

my_app/ │ ├── app.py ← Main Python file │ ├── templates/ ← ALL HTML files go here │ ├── base.html ← Shared layout │ ├── home.html ← Home page │ └── profile.html ← Profile page │ └── static/ ← CSS, JS, images └── style.css
⚠️
Critical

Flask automatically looks inside templates/ for HTML files. The folder name must be exactly that — no variations.

🔄 The Flow — Step by Step

Every time a user visits a page, this exact sequence runs:

1
🌐 User visits a URL

e.g. the browser requests /profile/alice

2
⚙️ Flask checks routes in app.py

It looks for a matching @app.route(...) decorator

3
▶️ Flask runs the matching Python function

If no match → 404 Not Found

4
🧠 Function prepares data

Fetch from a database, compute values, build dictionaries, etc.

5
📤 render_template() is called

You pass the HTML filename + all the data variables

6
🎨 Jinja2 injects data into the HTML template

Replaces all {{ }} and {% %} tags with real values

7
🖥️ Final HTML is sent to the browser

The user sees the fully rendered page

⚙️ Layer 1 — The Route (app.py)

This is where you define what URL does what.

Python — app.py 
from flask import Flask, render_template

app = Flask(__name__)

# When user visits "/profile/alice"
@app.route("/profile/<username>")   # dynamic variable
def profile(username):
    # Prepare whatever data you need
    user_data = {
        "name": username,
        "age": 25,
        "hobbies": ["coding", "reading", "gaming"]
    }

    # Send data to the HTML template
    return render_template("profile.html", user=user_data)
    #                      ^ which file    ^ key = value

if __name__ == "__main__":
    app.run(debug=True)
Key Takeaways
🔗
@app.route(...)

Defines the URL that triggers this function

📤
render_template("file.html", key=value)

Links Python → HTML. The key name is what you use in the template.

🔀
<username> in the URL

Dynamic segments — gets passed as a function argument automatically

🎨 Layer 2 — Jinja2 Templates

Jinja2 syntax lives inside your HTML files. Three symbols to know:

{{ }}
Output a variable
{% %}
Logic / control flow
{# #}
Comments (hidden)
{{ x | upper }}
Filters / formatting
HTML + Jinja2 — profile.html 
<!DOCTYPE html>
<html>
<body>

  <h1>Hello, {{ user.name }}! 👋</h1>
  <p>Age: {{ user.age }}</p>

  <h3>Hobbies:</h3>
  <ul>
    {% for hobby in user.hobbies %}
      <li>{{ hobby }}</li>
    {% endfor %}
  </ul>

</body>
</html>
🔗
The Variable Name Link

The variable user in the HTML must exactly match the keyword you passed in render_template(..., user=user_data)

🧱 Layer 3 — Template Inheritance

Instead of copying the same navbar and footer into every HTML file, create one base layout — all pages extend it. Write once, use everywhere.
📄 templates/base.html — The Master Layout
base.html 
<!DOCTYPE html>
<html>
<head>
  <title>{% block title %}My App{% endblock %}</title>
</head>
<body>

  <!-- Navbar — written ONCE, appears on ALL pages -->
  <nav>
    <a href="/">Home</a> |
    <a href="/about">About</a>
  </nav>

  <!-- Each page's unique content goes here -->
  {% block content %}
  {% endblock %}

  <!-- Footer — written ONCE -->
  <footer>© 2025 My App</footer>

</body>
</html>
📄 templates/home.html — A Child Page
home.html 
{% extends "base.html" %}    <!-- inherit base -->

{% block title %}Home{% endblock %}

{% block content %}
  <h1>Welcome to the Home Page! 🏠</h1>
  <p>This content is unique to home.</p>
{% endblock %}
✅
Both pages get navbar + footer automatically

No repetition. Just fill in the {% block content %} slot with what's unique to each page.

💡 The 3 Rules to Remember

1️⃣
render_template is the bridge

render_template("file.html", key=value) — whatever you name key, use {{ key }} in the HTML. Names must match exactly.

2️⃣
HTML files must live in templates/

Flask automatically looks inside a folder called templates/. It won't find files anywhere else.

3️⃣
Use inheritance to avoid repetition

Use {% extends "base.html" %} + {% block %} to write your layout once and reuse it everywhere.

🧪 Mental Test — /dashboard Page

Can you build a /dashboard page that shows a username and list of tasks?

  • 1 Create the route in app.py — @app.route("/dashboard")
  • 2 Prepare the data — a username string + a tasks list
  • 3 Pass it to a template — render_template("dashboard.html", username=..., tasks=...)
  • 4 In dashboard.html — use {% extends "base.html" %}, display {{ username }}, loop through tasks with {% for task in tasks %}
